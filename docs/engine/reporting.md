# Execution Reporting

`report.json` is a machine-readable execution summary generated by
`internal/engine/report` at the completion of a run. It records run-level
status, timing, step outcomes, registered artifacts, and structured error
diagnostics.

The report is written atomically to `<runRoot>/report.json` in CLI runs, and to
`<runRoot>/jobs/<jobID>/report.json` in API runs.

## Top-Level Fields

| Field | Type | Description |
|-------|------|-------------|
| `schemaVersion` | string | Contract version string (`"1.0"`). |
| `status` | string | Run outcome: `"success"`, `"failed"`, `"canceled"`, or `"timeout"`. |
| `planHash` | string | SHA-256 hash of the execution plan. |
| `dslHash` | string | SHA-256 hash of the authoring DSL source. |
| `profile` | object | Active profile configuration (omitted if no profile was active). |
| `runtime` | object | Global runtime configuration and timing information. |
| `jobs` | array | Ordered array of per-job execution reports. |
| `artifacts` | array | List of registered completion artifacts across all jobs. |
| `error` | object | Structured error summary (present on failure, omitted on success). |

## Runtime Object

| Field | Type | Description |
|-------|------|-------------|
| `startedAt` | string | ISO 8601 UTC timestamp of execution start. |
| `endedAt` | string | ISO 8601 UTC timestamp of execution completion. |
| `durationMs` | integer | Total duration in milliseconds. |
| `workerCount` | integer | Number of parallel workers configured. |
| `stepTimeoutSeconds` | integer | Per-step timeout limit in seconds. |
| `maxRetries` | integer | Maximum step retries configured. |

## Jobs and Steps

### JobReport

| Field | Type | Description |
|-------|------|-------------|
| `jobId` | string | Deterministic canonical job identifier. |
| `productKey` | string | Target product execution key. |
| `expectedArtifacts` | array | List of artifact filenames declared in the handoff package. |
| `steps` | array | Ordered list of step execution records. |

### StepReport

| Field | Type | Description |
|-------|------|-------------|
| `index` | integer | Zero-based step position within the handoff package. |
| `type` | string | Planner step type (`WriteCSV`, `WriteExportManifest`, `RunCADRuntime`). |
| `status` | string | Step outcome: `"success"`, `"failed"`, `"skipped"`, `"canceled"`, `"timeout"`. |
| `attempts` | integer | Number of attempts made for this step (0 if skipped). |
| `startedAt` | string | Step start UTC timestamp (omitted if step was skipped). |
| `endedAt` | string | Step end UTC timestamp (omitted if step was skipped). |
| `durationMs` | integer | Step execution duration in milliseconds (omitted if skipped). |

> [!NOTE]
> Unreached steps appear in the report with `status: "skipped"` and `attempts: 0`,
> preserving full visibility into the planned pipeline even after an early step
> failure.

## Artifacts Array

| Field | Type | Description |
|-------|------|-------------|
| `productId` | string | Product key associated with the artifact. |
| `type` | string | Artifact format type (`csv`, `json`, `step`, `pdf`). |
| `filename` | string | Artifact file basename. |
| `path` | string | Relative file path in the artifact store. |
| `checksumSHA256` | string | SHA-256 checksum of the artifact file (optional). |
| `sizeBytes` | integer | File size in bytes. |

## Structured Error Summary

When execution fails, the `error` object contains detailed failure diagnostics:

```json
{
  "error": {
    "message": "observed metadata \"working_copy_sha256\" mismatch",
    "classification": "metadata_mismatch",
    "productId": "bracket",
    "stepId": "2",
    "retryCount": 0,
    "timeout": false,
    "canceled": false,
    "boundary": "engine",
    "category": "verification",
    "code": "metadata_mismatch",
    "stage": "verification_comparison",
    "attemptId": "freecad-attempt-1"
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `message` | string | Human-readable error description. |
| `classification` | string | Verification failure class or consumption failure code. |
| `productId` | string | Product where the failure occurred (omitted if empty). |
| `stepId` | string | Step index where execution failed (omitted if empty). |
| `retryCount` | integer | Number of retries attempted (omitted if zero). |
| `timeout` | boolean | `true` if failure was caused by step timeout. |
| `canceled` | boolean | `true` if failure was caused by cancellation. |
| `boundary` | string | Error boundary (`engine`, `runtime`). |
| `category` | string | Error category (`verification`, `runtime`). |
| `code` | string | Machine-readable error code. |
| `stage` | string | Specific stage where failure occurred. |
| `attemptId` | string | Identity of the failed execution attempt. |

## Determinism Guarantees

`report.json` construction is strictly deterministic:
- Jobs appear in scheduler output order.
- Steps appear in handoff package step order.
- Artifacts are sorted by `(productId, stepId, path, filename, type, checksumSHA256)`.
- Profile settings are serialized with lexicographically sorted map keys.
- Timestamps are normalized to UTC.
